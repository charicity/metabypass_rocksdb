# Metabypass 强模式实现与验证报告

本次实现快盘 blob 暂存、不可变慢盘数据段、容量背压与淘汰，以及不依赖快盘的完整恢复点。
默认的 `sync=false` 写入不等待慢盘发布；启用分层后，`sync=true`、`SyncBackup()` 和成功关闭都等待相应完整慢盘点。
旧的非分层模式保持原行为，首版不支持在线或离线转换既有库，不提供弱模式或 S3 后端。

## 实现、原理与链路

- [分离存储与迁移](../../../utilities/metabypass/tiered_storage.cc)：新写入进入快盘，后台把原始 blob 字节拆成最大 256 KiB 的不可变数据段；读取校验副本后同步数据、描述文件和目录。描述文件和恢复点的 `BLOB-MAP` 绑定具体字节范围，后续追加不会覆写旧点内容。
- [原生索引备份](../../../utilities/metabypass/backup.cc)：保留 WAL/元数据双队列、镜像线程和校验发布线程。候选点等待 blob 依赖时，镜像继续推进；依赖完整持久化后才替换恢复点指针。
- [入口与同步屏障](../../../utilities/metabypass/metabypass_db.cc)：前台在进入 DB 之前预留暂存预算；同步写在退出原生写入、释放准入锁后等待恢复点，允许多个请求由同一点覆盖。
- 空间压力通过 blob manager 的 `SealForSpace` 封口当前及待 flush 代的文件，保留代归属，不主动 flush memtable。已迁移文件先让新读取走慢盘，再等待旧本地读取结束并淘汰，避免持续读取饿死空间回收。
- 恢复校验全部依赖后，创建独立的 footer/描述版本；不会修改已发布索引和被旧点引用的数据段。不需要把整个库重新装入快盘。无存活引用的快盘孤儿文件会归档，避免永久占满预算。
- 失败唤醒容量与同步等待者，停止发布并拒绝新写入。慢盘屏障失败时，主 DB 中的写入可能已经可见，不承诺回滚。

具体接口、部署契约及限制见 [英文设计文档](tiered-storage.md)。

## 性能实验

[原始数据与完整命令](experiments/tiered-benchmark.json) · [复现实验脚本](experiments/tiered_benchmark.py)

Release 构建：`AUTO_CLEAN=1 DEBUG_LEVEL=0 make -j8 db_bench`。
每组 2,000 次 Put、value 1,024 字节、`sync=false`，重复 3 次，表中为各指标中位数。
总耗时先在每轮中计算“前台＋最终同步＋关闭”，再取中位数，因此不一定等于三列中位数相加。
不包含创建数据库的时间。Put 延迟采样在所有组中使用相同方法。

快目录位于 `/dev/shm`，慢目录位于 `/tmp`。本机只有一块虚拟磁盘，**没有完成真实 SSD/HDD 双设备实验**。
延迟注入作用于慢目录可写文件的每次 Append/Sync/Fsync，包含慢盘 blob 和索引镜像；不模拟设备带宽或全部文件系统调用。
正式性能测量在此前的全量/压力进程结束后执行；隔离重试在测量完成后启动。

4 MiB 暂存与现有 Metabypass 相比：

- 注入延迟时，前台耗时约减少 **98.2%**，包含同步和关闭的总耗时约减少 **31.9%**。
- 不注入延迟时，前台耗时接近，但总耗时约增加 **57.1%**；新格式的复制、读回校验、描述文件同步等工作有成本。
- 64 KiB 预算会频繁触发背压和文件轮转；不能用大预算下的前台结果推断小预算性能。

较快的前台会更早到达最终同步屏障，把尚未完成的索引镜像和 blob 迁移留给 `SyncBackup()` 等待。
尤其在延迟注入实验中，索引镜像仍逐操作更新 WAL；这一后台瓶颈不会因 value 先写快盘而消失。
因此不能把前台约 98% 的降幅当作整体吞吐提升。

### 恢复、空间与恢复点进度

两种分层配置的每轮实验均删除整个主索引和暂存目录，调用 Restore/Open，再校验全部 2,000 个 value。
恢复不读取独立测试记录；校验只在恢复完成后使用已知测试数据。

| 暂存预算 | 注入延迟 | Restore＋Open 中位数 ms | 慢目录逻辑字节 | 暂存峰值字节 | 最后发布点滞后 ms |
|---|---:|---:|---:|---:|---:|
| 4 MiB | 0 µs | 219.85 | 2299475 | 2124172 | 111.78 |
| 64 KiB | 0 µs | 866.78 | 2306444 | 64642 | 107.69 |
| 4 MiB | 1000 µs | 276.91 | 2299475 | 2124172 | 139.73 |
| 64 KiB | 1000 µs | 1109.18 | 2306444 | 64642 | 139.75 |

“最后发布点滞后”采样于关闭之后，表示最后那个点的指标，不是写入期间的延迟分布或固定 RPO。
慢目录空间按路径累加逻辑文件长度，硬链接重复计数，不代表物理分配空间；所有组的索引队列背压均为零。
blob 与历史数据段不做 GC，长期空间增长不能由这个小数据集推断。

- 最终 Status 专项：**53/53 通过**，使用独立 tmpfs 目录。
- 最终强制线程切换构建：16 个分层测试各重复 100 次，独立 tmpfs 目录，**1600/1600 通过**；每次测试上限 60 秒。

- 覆盖整块快盘目录丢失、未 flush blob、压缩、覆盖/删除、WriteBatch 原子性、迭代、再次启动、空间压力、并发读取、迁移/发布阶段 SIGKILL、中断恢复重试、已发布数据损坏、超预算拒绝和错误传播。
- 源码/格式、BUCK 重新生成一致性、Python、ldb、db_crashtest 和 dump 检查通过。仓库的 BUCK 检查脚本会在 BUCK 有未提交修改时跳过，因此另行比较了重新生成前后的完整文件。

全仓库检查**未通过**，不能据此宣称全仓库绿色：

- 普通全量完成计数 3,323，5 个失败：两个 BloomFilter 断言、两个 ColumnFamily 分片超时，以及 Prefetch 断言后崩溃。它们与此前调查的测试/环境问题一致。
- Status 全量完成计数 3,305，39 个失败：两个 BloomFilter 断言、Prefetch 崩溃，以及 36 个分片超时。这轮曾与重复普通全量和压力测试重叠；超时主要集中在外部 SST 测试。Metabypass 无失败。
- 全量检查期间还补充了恢复身份和迁移优先级修补，最终版本由上述专项回归和重复测试覆盖。重复的普通全量轮次为减少负载而中止，不计为通过。
- Workflow YAML 检查受缺少 Ruby 阻塞；C API 与 `main` 比较仍报告历史的 21 个函数及 5 个符号缺失。当前 1,745 个 C API 声明均有定义。本次未修改 C API。

Status 全量中的 **36 个超时分片全部在磁盘目录隔离复跑通过**（4 个工作进程，每分片仍限制 60 秒）。这支持将这些新增超时归因于并发负载，而非分层存储功能失败；原始失败仍如实保留在检查记录中。普通全量的两个 ColumnFamily 超时分片也分别通过了隔离复跑（10/10 与 9/9，约 37 秒，仍使用 60 秒限制）。

## 实际边界

当前快盘预算是逻辑字节与预留预算，不是整个进程内存或文件系统物理占用上限。
前台分层写入准入采用串行锁；远端读取按逻辑文件访问不可变段，小同步写可能产生较多段和描述版本。
这些是首版可维护性与一致性取舍，不能预先断言所有工作负载都会加速。
目录移除、SIGKILL、tmpfs 和延迟注入验证的是协议行为，不是实际掉电介质保证。
